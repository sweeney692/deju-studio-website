# Summaries

Human-readable change summaries, one per major work session. They complement
`CLAUDE.md` (which is the always-current operating manual) by preserving the
"what we just did and why" for each shipped change. Useful when picking up a
project days or weeks later.

Filename convention: `YYYY-MM-DD-<short-slug>.md`.

Don't keep stale summaries up to date - they're a snapshot at the time of
writing. If something they describe is no longer accurate, update `CLAUDE.md`
or the relevant `README.md` instead and let the summary stand as a historical
record.
